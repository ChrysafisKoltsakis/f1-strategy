# Working on this project

F1 pit-strategy thesis project. Start with `README.md` (what each notebook does, rebuild order, results) and `docs/research_notes.md` (methods, open risks, and in section 6 the numbered next steps with the latest results).

## Conventions the user has set

- **Testing a change:** run it on at least two dry races -- one the same as in the previous test (for a before/after comparison; Canada 2023 `2023_r08` and Spain 2024 `2024_r10` are the usual repeats) and one new race each time. Include at least one race with a safety car when the change touches SC/VSC behaviour.
- **Commits:** don't commit or push until the user asks. Work happens on a branch (currently `fix-backtest-scoring`), not `main`.
- **Results are reported honestly**, including negative ones, with 95% bootstrap CIs over races; nothing is chosen by looking at the test races (e.g. Pirelli's first-listed strategy is used even where another option turned out better).

## Practicalities

- Python venv at `.venv`; `data/` is gitignored and regenerated by the notebooks (see README "Rebuilding and running"). The FastF1 API allows ~500 calls/hour; `01` resumes where it stopped.
- Streaming needs Java 17 and a local Kafka broker (README "Streaming layer"); the dashboard (`dashboard/server.py`) launches 08/09 itself.
- Long runs: `06 --position --strategy` takes 1-2 hours; `15` ~30 min. Run them in the background.
- Notebook files start with digits, so they are imported with `importlib` (see the top of any notebook), not `import`.
